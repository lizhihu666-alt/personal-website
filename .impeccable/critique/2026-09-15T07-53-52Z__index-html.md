## Overall Impression

这是一份「工艺已经过硬、但自我认知还没收口」的作品集。第一眼很稳：配色统一、动效克制、控制台零报错（6 种组合实测 console error / warning / pageerror 全为 0）。滚到 Method 章节时它真的会让人停一下——蓝色抛物线穿过整个视口的瞬间，是全站最有说服力的「作者感」时刻。

最大的落差在「表态」和「兑现」之间。站点到处写着术语式的承诺（`VERIFIED PROFILES`、`FORMAL RESUME`、`MODAL STRING SIMULATION`），但兑现层面有几处是空的：LinkedIn / GitHub 两个链接指向平台首页而不是 Leo 的档案；宠物摄影章节有 3 张照片的精确参数（50mm f/1.8 ISO 200、光位说明、拍摄故事），但 `src/` 与 `public/` 下没有任何一张图片文件（全站 `imgCount: 0`），页面上是内联 SVG 画的低对比剪影。

单个最大的机会：把 Method 章节那种只属于 Leo 的设计语言推广到摄影与生活章节，并用真实照片替换剪影。那一步做完，这个站会从「一个很专业的暗色作品集」变成「一看就知道是谁的站」。

## Priority Issues

**[P1] 「VERIFIED PROFILES」卡片里的 LinkedIn / GitHub 链接指向平台首页**

- **What**：`src/components/work/WorkContact.tsx:136` 与 `:145` 的 `href` 分别是 `https://linkedin.com` 和 `https://github.com`，是平台首页而非 Leo 的个人档案；卡片底部还写着 `VERIFIED PROFILES`（已核实档案）。
- **Why it matters**：这是作品集唯一的高价值转化动作。招聘方点进去看到 LinkedIn 首页，第一反应不是「链接坏了」，而是「这个人连自己的链接都没检查」——信任成本比留空更高。
- **Fix**：换成两个真实档案地址；在拿到真实地址之前，先删掉 `VERIFIED PROFILES` 这行字，并把链接改成不可点击的「待补充」状态，别让用户点到平台首页。
- **Suggested command**：$impeccable clarify

**[P1] Method 章节的 TUNER 控件被页头盖住，鼠标点不到**

- **What**：`#tuner-toggle`（文字 `TUNER [T]`，11px，88×27px）位于 `src/components/work/WorkMethodDavide.tsx:938-948`；它所在的表头是 `absolute top-0 … pt-8`（同文件 :921），而外层舞台是 `sticky top-0 h-screen`（:870）。章节被钉住时该按钮恒定停在距视口顶部约 32px 处，而站点顶栏底边在 65px。实测在章节任意滚动位置对按钮中心点做 `document.elementFromPoint()`，命中的都是页头容器而不是按钮本身：鼠标点不到，视觉上也只剩若隐若现的 `TUNER [T]`。键盘按 `t` 能正常打开，面板本身 7 个滑杆工作正常。
- **Why it matters**：这是全站最强场景里唯一的交互入口，等于给一个惊喜时刻配了一把拿不到的钥匙——用户没机会知道自己错过了什么。
- **Fix**：让该控件的偏移避开顶栏（钉住状态下下移到 80px 以上），或改成随舞台一起滚动的非固定位置。
- **Suggested command**：$impeccable layout

**[P1] 顶栏两个模式按钮聚焦后没有任何视觉反馈**

- **What**：`#switcher-btn-work` / `#switcher-btn-life`（`src/components/navigation/Header.tsx:196` / `:210`）带 `focus:outline-none`，却没有任何 `focus-visible` 环。实测：首页 6 个可聚焦元素里有 2 个聚焦后完全无变化，`/#work` 的 29 个里有 2 个，`/#life` 的 18 个里有 2 个——全是这两个按钮，全站复现。
- **Why it matters**：键盘用户（以及所有靠 Tab 操作的人）在顶栏会「失联」：焦点停在一个看不见的位置，不知道该按 Enter 还是继续 Tab，顶栏在纯键盘路径里变得不可靠。
- **Fix**：给这两个按钮补 `focus-visible:ring-2`（用亮蓝 #5B89FF，与既有色板一致），保留 `focus:outline-none` 以免出现双环。
- **Suggested command**：$impeccable audit

**[P1] 手机端 MENU 按钮读不出名字**

- **What**：`#header-menu-toggle-btn`（`src/components/navigation/Header.tsx:227-234`）里的文字是 `<span className="hidden sm:inline">Menu</span>`，小于 640px 时被隐藏，只剩 4 个 1px 装饰小圆点；按钮有 `aria-haspopup` / `aria-expanded` / `aria-controls`，但没有可访问名。实测 390px 下该按钮为 `{"id":"header-menu-toggle-btn","text":"","aria":null}`。
- **Why it matters**：手机端顶栏没有导航链接，MENU 是唯一入口。读屏用户只听到一个「按钮」，语音控制用户无法按名字点它；视力正常的人还能靠形状猜，辅助技术用户完全无从下手。
- **Fix**：加 `aria-label="打开导航菜单"`，或让隐藏文字改用 `sr-only` 保留在无障碍树里。
- **Suggested command**：$impeccable audit

**[P2] 宠物摄影章节在描述不存在的照片**

- **What**：`src/data/portfolioData.ts:231-265` 有 3 条照片记录（Cooper / Mochi / Bagel），带 50mm、f/1.8、ISO 200、光位角度和拍摄故事，但记录里没有 `src` 字段，全站也没有任何图片文件（`src/` 与 `public/` 下 png / jpg / webp 数量为 0，`public` 只有 favicon.svg）；渲染层 `src/components/life/LifeView.tsx:495-540` 用内联 SVG 画了一个低对比剪影代替。
- **Why it matters**：摄影是靠作品说话的门类，参数越精确、缺图越刺眼。目前这个章节的说服力是负的——它证明了「参数可以编」，而不是「照片拍得好」。
- **Fix**：把 3 张真实照片放进去（`public/photos/` 即可，数据里补 `src` 字段）；若暂时没有，先把参数与故事降级为文字说明，别让精确参数悬在空位上。
- **Suggested command**：$impeccable harden
